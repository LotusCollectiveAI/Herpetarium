## Contracts Codex can rely on

**Runtime-status boundary:** shared artifact, prompt, model-route, and
evaluation contracts are wired and locally auditable. Standardized
`DecryptoObservation` enforcement, runtime `TraceEnvelope` emission/export,
and Herpetarium ingestion are not implemented yet; they are the next slice.
Current native telemetry is retained, but no run should enter an
`EvaluationRecord` or BotBuild promotion until that slice lands.

- Artifact identity: `id = name@version`, integrity `contentHash` (sha-256 canonical JSON), immutable once minted. Promotion is typed: `evaluateSeating(artifact, records, policy)` licenses validated seating only from a verifying `EvaluationRecord` (verdict `pass`, exact id+hash binding, optional required protocol/model route); `provenance.evalRefs` is informational only. Native Table call metadata currently marks the pilot seating unvalidated. The not-yet-adopted `TraceEnvelope` contract still needs validation status or an evaluation-record reference before runtime projection.
- Compiler output is byte-stable and equals genomeCompiler v2.0.0 text for the same genome (goldens enforce it).
- The exact Table actor-call treatment is substrate-owned: `CIPHER_ENCRYPT_CANDIDATE_POLICY_ID`, exact text, and content hash are immutable, and `composeCandidatePolicyTaskInstruction` reproduces compiled cluegiver directives → candidate policy → authoritative action/output contract. `inversion.ts` separately owns normalized target recovery and typed `hard_veto | soft_regenerate_once | pass` semantics; do not conflate actor self-checking with the role-isolated audit.
- **Carrier comparability — what transfers and what does not (release review, 2026-08-01).** Both repos call the same shared composer, and `resolveRoleCandidatePolicy` throws unless the seated policy matches the canonical id, text, AND hash, restricting it to the `cluegiver` role. So the **task-authority block is genuinely byte-identical** and a finding about the treatment does transfer. The **surrounding envelope is not identical**, and two asymmetries must be controlled or disclosed: (a) Table prepends an `## Operative strategy artifact` system preamble that Herpetarium's `finalizeCluePrompt` does not emit; (b) Herpetarium injects cross-game `formatScratchNotes(...)` — accumulated strategy from prior games in the series — between the base prompt and the authority block, which The Table has no equivalent of. Scratch notes are a **live confound**: `headlessRunner` populates them from `scratchNotesByTeam`/`scratchNotesMap`, and nothing forces symmetry between arms. **Run the promotion A/B with the `no_scratch_notes` ablation on both arms** (or with provably identical notes), and never describe a Table seat as running a prompt byte-identical to a Herpetarium arm — it is the same treatment inside a different envelope.
- `DecryptoObservation` cannot express opponent keywords; `code` is encryptor-only; `teamChatVisibility` is exactly the product's two worlds (`open | private`) and `assertRoleLegal` throws on opponent team-chat lines under `private`.
- Dialogue and full telemetry are research/training material by founder direction: traces carry `transcriptRef` by default; inline `transcript` requires an `operator_research` `exportStamp` (approvedBy + date) or validation fails. Repo source files remain bot-content-only — they are not an export channel.

**Calibration decisions (encoded in `shared/substrate/fixtures.ts`):** `BLIND_INVERSION_CALIBRATION_2026_08_01` records the 30-clue run (6/6 recovered, 5/6 flagged at 0.60, FACTORY missed at rank 2/conf .35; controls 1 flagged / 8 recovered of 24; $0.003187, 133s; proxy-control limitation stated). `PROVISIONAL_INVERSION_VETO_POLICY` fixes the tiers: hard veto = confidence ≥ 0.60 on a matching concept OR definition-shaped with directness ≥ 0.60; soft regenerate-once = rank-1 recovery at any confidence OR definition-shaped recovery at any rank; recovery-anywhere is never a veto (8/24 good clues blind-recoverable). **Measurement ceiling — added by the 2026-08-01 release review, `BLIND_INVERSION_LIVE_PROBE_2026_08_01`.** A third probe of 12 ordinary one-word base-advanced clues on the same pinned route hard-flagged only 2/12 and recovered a target at any rank in only 3/12. Read against 6/6 recovery on catastrophic definition-shaped phrases, the instrument's sensitivity is strongly concentrated on the pilot failure mode and low on ordinary play. The cause is structural, not sample size: `conceptRecoversTarget` in `inversion.ts` is **lexical** — a target token must reappear as a whole normalized token in a returned concept — so a purely semantic leak (`sword`→WARRIOR, `hive`→BEE) is undetectable by construction at any threshold. Raising or lowering 0.60 cannot fix this.

Consequences, decided in this review and encoded as `INVERSION_PROMOTION_PREREQUISITES`:

- **Family play: not a blocker.** The gate is a catastrophic-clue guardrail with a low over-regeneration rate (1/24 proxy controls hard-flagged). It reliably catches the exact thing that ruined the pilot and rarely fires on good clues. Its residual failure mode is "an ordinary-quality clue gets intercepted", which is Decrypto working as designed, not a product defect. It seats as-is, labeled probe-grade.
- **BotBuild promotion: blocking as a primary outcome.** Hard-flag counts are inadmissible as the headline metric for a promotion claim, because a treatment can drive hard-flags to zero while leaving every semantic leak intact — that measures compliance with a lexical filter, not opacity. Promotion requires a semantic-equivalence judge plus ceiling-free behavioral outcomes (interception rate, teammate-decode rate).
- **No new inline architecture.** The semantic judge runs **offline over durable traces**, not in the game path. Table already persists the auditor's full ranked concept list in `ai_calls.response_raw`, linked to the actor call via `call_meta.inversionAuditOfAiCallId` and carrying `cipherRoundIndex`; targets are recoverable by joining round code and team keywords. Retroactive semantic scoring of V1 family games is therefore already possible with zero added latency, cost, or gameplay risk. Do not add a second live model call per encrypt action for this.
- The frozen `PROVISIONAL_INVERSION_VETO_POLICY` object was **not** modified: hash `eb2c5141cbf771e4d701bcfbb34644f55f64b4da4cc19ea4d1947558ef7b3c57` is unchanged, verified by transcribing the pre-edit literal and re-hashing. New evidence and the raised research bar are adjacent records.

## Release review 2026-08-01 (Opus/Claude Code): blockers found AFTER the closure above

The review found eight defects. Fable fixed two during review; Codex's
subsequent release-blocker pass closed the remaining six. The descriptions
below preserve what the review found; the closure record follows them.

**Fixed here:**
- **[Table — FIXED] Bot strategy advice was written `visibility: "public"` unconditionally** (`games/store.ts`, `cipher_strategy_message`) while the client files those events into the **Team** channel, which under the default `private` mode is labelled "Only your teammates can read this." Two defects in one: a live intercept proposal (including its three-digit guess) was readable by the opposing team, and the padlock label was false. Now routed through `deriveHumanChatRouting({channel:"team", …})`, so private games store `team:<team>` and only that team receives the row; `channel`/`audience` added to the payload and to `PUBLIC_EVENT_PAYLOAD_SCHEMAS`. **The DB-backed cipher integration suite was NOT re-run** (no provisioned Postgres in the review environment) — re-run it before merge.
- **[Herpetarium — FIXED] The `random_clues` ablation fabricated actions inside strict mode.** `server/ai.ts` returned three `Math.random()` words with `parseQuality: "clean"`, so `strictFailure` in `headlessRunner.ts` evaluated false and the triple persisted with `usedFallback: false` and was played — a synthetic action in the mode that exists to guarantee none. It also passed the blind-inversion calibration's clean-control filter, contaminating control selection. Now `parseQuality: "fallback_used"`: strict fails closed, non-strict ablation arms are unaffected, and clean-only analysis excludes them.

**Originally open — resolved before family play:**
1. **Inversion-gate failure permanently fences the round.** A `gate_failed_closed` throw terminalizes the task, and `orchestrator.ts` counts `failed` tasks as `alreadyQueued` for the same logical action, so the scheduler never re-queues it. Only a manual host retry recovers. Compounding: the auditor is hardcoded to `provider: "openrouter"` regardless of seat, so the host-visible **"Stub (offline, deterministic)"** seat cannot complete a Cipher encrypt turn without an OpenRouter key, and the surfaced error is `ai_response_invalid`, which is not what happened.
2. **Budget reservation covers 1 of up to 4 paid calls per encrypt turn.** `reserveBudgetForTask` is called once per turn task; `runRecordedFollowupCall` (actor pass 2 and both audits) bypasses admission entirely, and the auditor runs at max reasoning effort. The documented "every live reservation counts against the cap" is false, and a host-set cap can be exceeded several-fold.
3. **Mobile task-first regression.** The fixed conversation dock occupies ~200px of a 390×844 viewport; at 320px the clue rows, all digit buttons, and the primary "Review answer" control are below the fold, and a clue renders broken mid-word ("Const/ellatio/n") from a fixed two-column grid at `min-[370px]`. This reproduces the pilot's "cluttered, doesn't teach the task" failure on the widths the family will actually use.
4. **Channel switch carries the typed draft to the new audience** with no confirmation, on 36px tab targets directly above Send — a plausible route to publishing a secret by mis-tap.
5. **Hard-veto rewrites a successful actor call as `status:"error"`/`failureStage:"parse"`**, overwriting the real `ok` status. The call succeeded and returned rule-legal clues; only `callMeta.inversionDisposition` retains the truth, and no read path exposes it. This corrupts exported research evidence.
6. **The "unvalidated" label reaches no human surface.** It exists in source, `call_meta`, and docs, and is stripped by every read projection; no UI string mentions it. Requirement 6 (an unvalidated artifact may be seated only explicitly and must be labeled) is met in code and unmet in product.

**Closure and validation (Codex, 2026-08-01):**

   A denied stage makes no provider call and follows the durable budget-fence
